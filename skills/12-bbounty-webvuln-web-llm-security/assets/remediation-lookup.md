# Remediation Lookup

| Observed boundary concern | Proportionate prevention | Safe verification criterion |
| --- | --- | --- |
| Untrusted content is not clearly separated | Preserve provenance and isolate untrusted content from trusted instructions | Authorized fixture remains labeled and does not alter the ordinary task outcome |
| Data access lacks a documented independent check | Enforce server-side identity, tenant, purpose, and least-privilege authorization | Documentation and approved normal use show the check before access |
| Tool request lacks a constrained action boundary | Use allowlisted operations, narrow schemas, and server-side parameter validation | Approved UI shows only intended options and confirmation boundary |
| Consequential action lacks user control | Require explicit, contextual confirmation and show intended effect | Normal-use flow displays the effect before commitment |
| Boundary decisions are not observable | Add privacy-preserving audit events and monitoring | Authorized reviewers can trace decision metadata without sensitive content |

Recommendations are design guidance, not implementation changes or proof that a control is effective.
