# Diagram Patterns

Use only the patterns relevant to the approved direction.

These are semantic grammars, not templates. Combine them when the content requires it and the board retains one global navigation grammar.

## Architecture and infrastructure

Best for:

- components
- services
- deployment
- trust zones
- data flow
- ownership boundaries

Possible local mix:

- layered architecture for components
- swimlanes for ownership
- trust-boundary frames
- small sequence strip for one critical request path

Do not conflate:

- code dependency
- runtime call
- network connection
- deployment containment
- data ownership

Give each edge class a distinct, documented semantic treatment.

## Process and state

Best for:

- procedures
- workflows
- reactions
- decision systems
- lifecycle

Use:

- one dominant direction
- diamonds only for actual conditions
- explicit terminal states
- exception routes separated from the happy path
- loops routed outside the main spine

For complex processes, combine a high-level flow with a detail frame for exceptions or state transitions.

## Concept and knowledge map

Best for:

- books
- research subjects
- theories
- lore
- study boards

Use:

- a central thesis or organizing question
- clusters based on real categories
- typed relationships
- restrained cross-links
- visible distinction between fact, interpretation, and uncertainty

Avoid a generic radial mind map when hierarchy, chronology, or comparison would explain the subject better.

## Timeline and narrative

Best for:

- historical events
- book plots
- project evolution
- character arcs
- incident sequences

Possible mix:

- primary timeline spine
- parallel lanes for factions or systems
- causal callouts
- a consequence or theme panel

Do not imply exact chronology when only rough ordering is known.

## Comparison and taxonomy

Best for:

- alternatives
- species/classes/factions
- technologies
- chemical families
- design options

Use:

- stable comparison criteria
- aligned rows or columns
- category frames
- exceptions visibly separated
- concise evidence notes

Do not force incomparable items into a symmetric matrix.

## Layered anatomy

Best for:

- systems
- organisms
- mechanisms
- protocols
- chemical structures at an explanatory level

Use:

- outside-to-inside or top-to-bottom layers
- callouts tied to exact regions
- one detail zoom for dense mechanisms
- stable boundary semantics

Do not imply physical containment when the relationship is conceptual.

## Sequence strip

Best for:

- API request paths
- conversations
- protocols
- turn-based RPG procedures
- reaction stages

Use:

- actors aligned consistently
- messages or transitions ordered visibly
- conditions and branches in dedicated subregions
- timing only when supported

For a large system, embed a sequence strip as a local region inside an architecture board.

## Annotated specimen

Best for:

- maps
- objects
- creatures
- interfaces
- chemical apparatus
- character equipment

Use:

- one dominant visual object or schematic
- numbered or direct callouts only when numbering conveys reference order
- concise annotations
- dedicated legend for repeated symbols

Do not fabricate visual details absent from the source.

## Threat model and attack path

Best for:

- assets
- actors
- trust boundaries
- controls
- hypothetical attack routes

Use:

- trust-zone frames
- distinct asset and actor shapes
- warning/exception accent only for evidenced or explicitly hypothetical hostile paths
- controls positioned at the boundary or step they affect
- assumptions and uncertainty visible

Do not turn a dependency arrow into an attack path without evidence.

## RPG and worldbuilding atlas

Possible coordinated frames:

1. world or faction overview
2. relationship web
3. chronology or campaign route
4. rules/procedure reference
5. character or artifact deep dive

Maintain canon status visibly:

- established
- rumor
- character belief
- GM-only
- interpretation

Never let visual polish erase deliberate mystery.

## Chemistry and science board

Possible local mix:

- taxonomy or concept hierarchy
- process/reaction flow
- annotated apparatus
- conditions and safety notes
- comparison matrix

Preserve:

- formulas
- units
- phases
- catalysts
- reversible direction
- assumptions
- model limitations

A teaching simplification must be labelled as such.

## Multi-board atlas

Use when no single board can preserve both overview and precision.

Common architecture:

- frame 1: orientation and thesis
- frame 2: structural map
- frame 3: dynamic process
- frame 4: reference, exceptions, or evidence

Each frame must have:

- a distinct job
- a clear entry point
- stable visual semantics
- an optional maker mark only when explicitly requested
- links or visual cues showing how it relates to the other frames
