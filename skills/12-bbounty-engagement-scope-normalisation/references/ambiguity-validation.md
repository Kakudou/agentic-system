# Ambiguity and Conflict Controls

## Purpose and Preconditions

Identify documentation uncertainty before normalized scope is handed to an engagement team. This is record validation against supplied evidence, not target validation. Start with admitted sources and the completed identifier/restriction matrix.

## Documentation Methodology

Compare each normalized row to its source quotation. Check that identifier type, inclusion status, restrictions, dates, and source version are present. Record ambiguities as discrete questions with the competing citations, impact, conservative status, and accountable owner. Use the ambiguity/stop checklist to ensure that material unknowns are visible.

## Uncertainty and Scope Controls

Stop and escalate when sources conflict; an identifier boundary is unclear; an exclusion may apply; source authority or freshness is unknown; or a requested interpretation would add a target or permission. Never resolve uncertainty with DNS, HTTP, range calculations, discovery, scanning, or other active or target-expanding activity.

## Evidence and Handoff

Label every item `resolved`, `pending-clarification`, or `stop`. A resolved item requires an authoritative citation or written clarification from the authorized source authority. The handoff must distinguish confirmed documentation from unresolved operational authorization.

## Authoritative Sources

- Current admitted engagement sources and their documented revision history.
- Written determinations from the authorized source owner.
- NIST SP 800-115 for authorization and rules-of-engagement context: https://csrc.nist.gov/pubs/sp/800/115/final
