# Versioned Evidence and Handoff

## Purpose and Preconditions

Package normalized scope as a bounded, reviewable handoff. Require a completed source register, identifier/restriction matrix, ambiguity register, engagement recipient, and handoff date.

## Documentation Methodology

Assign a handoff version and effective date. List every admitted source with version or freshness marker, every normalization decision, each unresolved item, and the package limitations. Maintain stable source IDs so reviewers can trace each row to the quoted evidence. Describe a revised package as superseding a prior handoff only when its source basis and changes are recorded.

## Uncertainty and Scope Controls

Do not represent the package as permission independent of its sources. Do not silently replace a prior version, remove unresolved items, or imply target ownership, reachability, or eligibility. The handoff is documentation only and must state that it contains no target expansion or active validation.

## Evidence and Handoff

Use the engagement handoff template. Include recipient, version, effective date, source register, normalized matrix, restrictions, stop items, and required follow-up. Require the recipient to obtain owner clarification before acting on any `pending-owner` or `stop` item.

## Authoritative Sources

- The admitted engagement evidence and authorized owner clarifications.
- NIST SP 800-61 Rev. 2 for evidence handling context: https://csrc.nist.gov/pubs/sp/800/61/r2/final
- ISO/IEC 27037:2012 for identification and preservation principles.
