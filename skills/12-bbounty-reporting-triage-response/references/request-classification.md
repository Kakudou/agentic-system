# Request Classification

## Purpose

Organize an admitted triage record for factual review without deciding validity, severity, duplicate status, reward, or closure.

## Preconditions

- The triage record is admitted and its quote or source locator is preserved.

## Documentation Methodology

Apply one primary label: clarification, status notice, duplicate or merge notice, severity or impact question, closure notice, or unclassified. Quote the language that supports the label. If a record contains multiple requests, record each separately. Use `unclassified` where wording is ambiguous; do not classify from keywords alone or infer an unstated request.

## Boundary

Classification is an internal index, not a platform action or a negotiation position. Do not formulate a reply, contest a decision, or retest to resolve ambiguity.

## Evidence And Handoff

Attach the request quote, label, ambiguity notes, and the next factual question, if any. Escalate unclear or compound requests to the authorized reviewer.
