# Existing Skill Resolution

Read this only when an exact-name or materially similar skill is found.

## Similarity Test

Treat a skill as materially overlapping when most of these are true:

- same user goal/problem class
- same triggering language
- same primary inputs
- same core procedure
- same output/side effect

Shared vocabulary alone is not enough.

## Resolution Options

### Extend / update existing

Prefer when the new retrospective improves the same capability without changing its identity.

Preserve stable behavior unless the user explicitly approves a breaking change.

### Overwrite existing

Use only when the user explicitly chooses replacement and the new package supersedes the prior intent.

Before overwrite, preserve or display the intended diff when the environment supports it.

### Create a new skill

Use when the capability is distinct enough to deserve independent activation or the user explicitly asks to keep both.

Choose a name that describes the distinct capability; do not append arbitrary numeric suffixes merely to avoid deciding scope.

## Required User Decision

When the correct action is ambiguous, present:

- existing skill name
- one-sentence overlap summary
- recommended option and why
- choices: `extend`, `overwrite`, `new`, `abort`

Do not write persistently until the choice is resolved.
