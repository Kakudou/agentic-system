# Source And Ownership Admission

## Purpose

Establish that an already observed public artifact is within authorized scope and plausibly operated by the named target before calling it an exposure.

## Preconditions

- Written authorization, target scope, and reporting channel are available.
- The artifact locator was supplied by the program, asset owner, or prior approved observation.

## Method

Use only the supplied locator and ordinary public context already visible in the approved observation. Compare the stated target, host or distribution identity, and program scope. Record attribution as confirmed only when a target-controlled identity or the program documentation supports it; otherwise use `unconfirmed`.

Do not resolve adjacent names, follow links to other assets, query registries, inspect repositories, or infer ownership from a filename or platform alone.

## Interpretation And Controls

Shared hosting, CDNs, package registries, contractors, and third-party integrations can make public artifacts appear target-owned. A public response alone establishes neither ownership nor unintended exposure. Treat conflicting or incomplete attribution as out of scope until the owner confirms it.

## Evidence And Handoff

Record the authorization reference, redacted locator, attribution basis, observation time, and uncertainty. Send unconfirmed ownership cases only to the designated triage channel as a request for scope confirmation.
