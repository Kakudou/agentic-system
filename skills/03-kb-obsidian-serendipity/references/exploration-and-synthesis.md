# Exploration and Synthesis

The purpose of exploration is to gather enough neighboring knowledge to produce a useful coherent
result.

It is not a graph-analysis exercise.

## Expansion Priority

Prefer, roughly in this order:

1. explicit links from the seed;
2. generic parent or derived siblings when the zettel model exposes them;
3. strong semantic neighbors from `kb-obsidian-search`;
4. a smaller number of related notes that add contrast or a missing angle.

Avoid collecting several notes that all restate the same claim.

## Bounded Exploration

Stop expanding when one of these becomes true:

- the selected set already supports a coherent thread;
- new candidates mostly repeat existing material;
- new notes are only weakly related;
- further expansion would require vault-wide crawling;
- the evidence boundary has been reached.

Serendipity comes from recombining good notes, not from maximizing hop count.

## Generic and Derived Zettels

When the seed is a derived zettel:

- read its generic parent when available;
- consider other derived zettels pointing to the same generic idea when discoverable through the
  normal search contract.

This is useful because the generic note supplies the reusable principle while derived siblings show
how the principle behaves in other concrete contexts.

Do not mutate the parent to create reciprocal links.

## Synthesis Shape

Prefer a normal piece of writing over a mechanical zettel-by-zettel report.

A good synthesis usually has:

- one central idea;
- enough context to understand why the selected notes belong together;
- evidence or examples from the zettels;
- explicit tensions or limits when they matter;
- a conclusion that follows from the selected material.

Do not force headings if a few paragraphs are enough.

## No Mandatory Novelty

The skill is successful when the result is useful and coherent.

It does not have to discover a surprising connection every run.
