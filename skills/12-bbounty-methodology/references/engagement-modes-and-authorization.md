# Engagement Modes And Authorization

## Purpose

Classify the engagement and establish whether any work may begin.

## Preconditions

- Named target and requester context.
- Current program terms or written owner authorization.

## Process

1. Classify as `contractual` only when current program terms govern the target.
2. Classify as `independent-authorized` only when an authorized owner has defined the target, permitted activity, timeframe, and disclosure contact in writing.
3. Record the authorization source, effective period, and restrictions. Escalate conflicts to the program or owner.

## Limits

- Public availability, passive discoverability, or a bug bounty brand is not authorization.
- Never reinterpret missing terms as permission or use an authorization for a different asset or purpose.

## Evidence And Handoff

Hand off an engagement decision, authorization reference, permitted boundary, expiry, and restrictions to scope admission. Block if any required element is unavailable.
