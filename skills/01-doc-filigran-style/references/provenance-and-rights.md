# Provenance and Rights

Load this reference for every request. It governs domain-specific authority, source registration, freshness, public-source limits, licensing, trademarks, assets, credits, and conflict handling. It does not provide legal advice or certification.

## Domain-Specific Hierarchy

Apply in order, within the question's domain:

1. current brand-owner-approved instructions/assets for the actual deliverable;
2. official public Filigran Identity for corporate-media logo, corporate palette, typography, imagery, and messaging;
3. other current official Filigran corporate sources, newsroom, and kits;
4. Filigran UI documentation for documented product-UI semantics/component intent;
5. pinned UI source/package for actual behavior;
6. inferred adaptations;
7. local editorial choices.

Never blend conflicts into a synthetic rule. UI tokens do not override corporate identity. When a product-UI-inspired technical expression is selected, pinned UI evidence may govern only non-brand surfaces, elevation, layout rhythm, component character, and accurate status semantics; the static translation remains `[IA]`. Scope each claim to its source/domain, preserve competing evidence, and request owner direction where consequential.

## Evidence Record

Every material claim records:

| Field | Required content |
|---|---|
| ID | Stable local identifier |
| Class | Exactly one of `[DR]`, `[IE]`, `[IA]`, `[LEC]` |
| Claim | Testable and domain/medium scoped |
| Source | Full URL, supplied authority, or explicit local-choice owner |
| Freshness | Access date; page update, commit, package, or kit version when available |
| Confidence | High/medium/low, with reason if not high |
| Conflict/uncertainty | Competing evidence, ambiguity, or missing authority |
| Rights/approval | Asset permission, credit, approval status, or decision owner |

- **[DR]** is only for explicit authoritative documentation or supplied approved instructions.
- **[IE]** is for inspected evidence or observed fact in a named official artifact, bounded source review, pinned product UI source, package, component, or official implementation; it is not automatically corporate-media law.
- **[IA]** is a reasoned static-media translation with rationale, never “official.”
- **[LEC]** is a project choice with approval ownership when consequential.

Source-absence findings must be bounded as “not found in the reviewed sources,” never stated as universal absence.

### Supplied Visual Reference Evidence

Treat a supplied screenshot, deck, image, mood board, or other visual reference as evidence only for what can actually be inspected. Record:

- stable reference ID, supplier/local owner, provision or access date, and filename/version when available; if an actual hash is generated or supplied, record it with its algorithm, using `SHA-256: <digest>` by default;
- what is directly observed: canvas tone, surface hierarchy, spacing rhythm, typography character, density, component character, status treatment, logo variant, or other specific traits;
- the supplier's stated intended authority: approved instruction, UI implementation evidence, adaptation input, visual preference, or comparison-only;
- inspectability limits, rights/redistribution constraints, conflicts, and approval status;
- which traits are adopted, rejected, or changed and the resulting `[DR]`, `[IE]`, `[IA]`, or `[LEC]` class.

Visual similarity never creates corporate authority, asset rights, or permission to extract a mark. Inspect matching supplied references before theme choice, but do not infer hidden tokens, fonts, editability, interaction, or approval from pixels alone.

## Freshness Triggers

Re-retrieve authoritative pages/assets when:

- work begins after the recorded access date and currentness matters;
- a logo, product mark, kit, font archive, boilerplate length bucket, company/product description, statistic, funding figure, executive, product name, or credit is used;
- the deliverable has new brand-owner instructions or supplied assets;
- a Zeroheight page reports an update or differs from the brief baseline;
- a UI token, component, import path, package version, icon count, loader behavior, release state, or license term is claimed beyond the pinned snapshot;
- docs and source conflict, or the target artifact uses a different package/commit;
- publication, redistribution, third-party imagery, embedding, or a new channel changes rights requirements.

Date the chosen baseline. Fresh retrieval does not itself grant usage, redistribution, trademark, or publication rights.

## Public-Source Authorization Limits

- Public viewing permits source-grounded analysis and citation; it does not by itself authorize official representation, trademark use, asset redistribution, publication, or modification.
- The [Media kit overview](https://zeroheight.com/020822383/p/55c9e8) says its assets may be used in communications about Filigran. Still record intended communication, provenance, credit, asset/version, restrictions, and approval context.
- Retrieve official kits through [Logo](https://zeroheight.com/020822383/p/172a6b) and [Resources](https://zeroheight.com/020822383/p/141a98), not copied transient/signed download URLs.
- Do not bundle or expose official kits, binaries, SVG paths, photos, fonts, templates, or transient links in this skill package.
- Do not infer broad redistribution, derivative-work, sublicensing, or publication rights from access to a page or file.

## Conditional Asset Acquisition / Copy Register

Apply this register when the workflow actually acquires or copies an approved logo, product mark, photo, icon, illustration, font, or supplied template, or prepares that file for a deterministic downstream embedding handoff. If no file is acquired/copied or prepared for embedding, retain ordinary source/rights provenance and do not block a specification for lack of file hashes or local paths.

For each applicable file record:

- asset ID, exact final filename and version;
- downloaded archive filename when applicable, exact archive member path, exact extracted member/file name, and authorized deterministic local path;
- each generated or available digest labelled with its algorithm, using `SHA-256: <digest>` by default; never record an unlabeled digest;
- source page/provider and retrieval date;
- intended deliverable/use;
- authorization/approval reference;
- modification and redistribution limits;
- required credit and rights holder where known;
- expiry/channel restrictions;
- actual variant/crop/color treatment;
- downstream deterministic embedding/resolution and render/export verification handoff;
- unresolved metadata and status.

If consequential rights or credit remain unclear, stop that asset's use or use an approved mark-free/asset-free alternative.

Do not package proprietary assets in this portable skill or substitute a transient/signed URL for a deterministic handoff. A source URL registers provenance; when a file is actually acquired/copied or prepared for deterministic embedding, it does not replace the exact archive/member/filename/version, authorized local path, and generated or available `SHA-256: <digest>` records needed by downstream creation.

## Provenance Completion Check

Verify every `[DR]`/`[IE]` source; full URLs and dates; commit/packages for UI claims; supplied-reference observations and intended authority when references exist, or an explicit none-supplied record; corporate-vs-UI domain separation; current kit/boilerplate retrieval when used; asset credits; visible conflicts; explicit local choices; no proprietary bundling or exposed transient links; and brand-owner approval `UNVERIFIED` unless actual evidence was supplied. When asset/font acquisition, copying, or deterministic embedding handoff actually occurs, also verify exact source/archive/member/filename/version, authorized local paths, embedding/export handoff, and generated or available hashes labelled `SHA-256: <digest>`; otherwise do not block the specification for absent file hashes.
