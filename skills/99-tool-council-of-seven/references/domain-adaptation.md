# Domain Adaptation

The seven lenses stay fixed. Adapt **what counts as evidence** to the artifact.

## Code and software

- Keima: bugs, security, failure modes, races, edge cases.
- Kakugyō: interfaces, coupling, state, boundaries, dependencies.
- Fuhyō: duplication, abstraction overhead, unnecessary dependencies.
- Kyōsha: idioms, standards, prior art, platform constraints.
- Hisha: naming, API ergonomics, developer/user experience, clarity.
- Kinshō: maintenance, runtime/infra cost, delivery complexity.
- Useful evidence: tests, static analysis, runtime behavior, benchmarks, diffs, logs.

## Architecture and infrastructure

- Keima: failure domains, operational hazards, hidden dependencies.
- Kakugyō: topology, ownership, data/control flow, interfaces.
- Fuhyō: needless services/layers, over-decomposition.
- Kyōsha: established deployment/operational patterns.
- Hisha: operator ergonomics, observability clarity, configuration UX.
- Kinshō: cloud/resource cost, operational burden, staffing complexity.
- Useful evidence: diagrams, SLOs, load characteristics, failure tests, cost data.

## Creative or professional writing

- Keima: contradictions, unsupported claims, continuity failures.
- Kakugyō: argument/narrative structure and information sequencing.
- Fuhyō: repetition, padding, unnecessary exposition.
- Kyōsha: genre/context/precedent where relevant.
- Hisha: prose, rhythm, tone, voice, readability, presentation.
- Kinshō: audience fit, length versus value, production effort.
- Useful evidence: passages, outline, brief, audience requirements, source material.

## Research and analysis

- Keima: unsupported inference, confounders, missing counterevidence.
- Kakugyō: methodology, chain of reasoning, source-to-claim structure.
- Fuhyō: redundant analysis, needless complexity.
- Kyōsha: literature/context/competing explanations.
- Hisha: clarity of charts, prose, framing, information hierarchy.
- Kinshō: research effort versus decision value.
- Useful evidence: primary sources, datasets, calculations, citations, methods.

## UX, product, and visual design

- Keima: broken flows, inaccessible or misleading states, edge conditions.
- Kakugyō: hierarchy, information architecture, interaction structure.
- Fuhyō: visual/interaction noise, unnecessary steps.
- Kyōsha: patterns, comparable products, platform conventions.
- Hisha: composition, typography, polish, affordance, consistency.
- Kinshō: implementation cost versus user value.
- Useful evidence: actual renders, screenshots, prototypes, user flows, accessibility checks.

## Images and media

- Keima: obvious artifact errors, continuity/composition failures.
- Kakugyō: structural balance and composition.
- Fuhyō: visual noise and unnecessary elements.
- Kyōsha: relevant art/media context and references.
- Hisha: color, style, craft, visual coherence.
- Kinshō: production complexity and practical use.
- Useful evidence: actual image/video/audio, reference images, technical specs.

## Plans and strategy

- Keima: assumptions, failure scenarios, hidden dependencies.
- Kakugyō: sequencing, ownership, dependency graph, feasibility.
- Fuhyō: scope and unnecessary workstreams.
- Kyōsha: prior art, external conditions, alternative strategies.
- Hisha: communication, stakeholder comprehension, usability of the plan.
- Kinshō: expected value, opportunity cost, resource allocation.
- Useful evidence: milestones, budgets, constraints, historical data, scenarios.

## Recipes and physical procedures

- Keima: safety, failure points, substitutions.
- Kakugyō: technique order and process flow.
- Fuhyō: redundant steps/ingredients.
- Kyōsha: culinary/craft precedent and technique.
- Hisha: sensory result, presentation, clarity.
- Kinshō: cost, availability, effort, waste.
- Useful evidence: temperatures, quantities, technique constraints, actual outcome.

## Mixed-domain work

Do not force one domain profile. Apply each seat to the portions where its evidence is meaningful, then synthesize across boundaries.
